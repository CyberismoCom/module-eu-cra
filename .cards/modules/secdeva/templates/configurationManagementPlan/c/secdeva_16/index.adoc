== Introduction

Configuration Management (CM) is the systematic process of identifying, controlling, and tracking all components of a software system throughout its development, testing, deployment, and maintenance lifecycle.

Configuration management covers how different _configuration items_ are managed in terms of the following aspects:

* Storage and tooling
* Access control
* Versioning and unique identification
* Change history
* Authorisation of changes
* Acceptance
* Integrity protection
* Backup and recovery

== Relationships between configuration items

The configuration items documented in this plan are interdependent. The following relationships should be considered when managing changes:

* *Source code* is the foundation. Changes to source code may affect the build system, test plans, test reports, and technical documentation.
* *Build system* consumes source code and third-party components to produce release artifacts.
* *Risks* and *Security issues* require amendments to the requirements and source code
* *Requirements* drive technical documentation, source code implementation, and test plans.
* *Technical documentation* describes the design that is implemented in source code and validated by tests.
* *Test plans and test reports* validate that source code meets the requirements and address the security issues.

When a configuration item changes, consider whether dependent configuration items also need to be updated.

== Configuration management lifecycle and configuration list

Configuration management is commonly based on the concept of a baseline, which determines a stable starting point, after which strict configuration management controls will be applied. When configuration management controls are applied, the configuration management system shall include a list of all configuration items that comprise the product.
